					<span style="font-size: 18px"><b>Status Pages 2.0 - Now With Pizza!</b></span> <br />

			<tr>
				<td colspan="2">

				<td colspan="3" class="article">
					<br /><div align="left"><div align="center"><a href='https://redirect.pizza/?utm_source=partner&amp;utm_medium=banner&amp;utm_campaign=hackthissite.org' target='_new'><img src='https://data.htscdn.org/images/redirect-pizza.png' /><br />
<br />
<b>Redirect.Pizza - Tasty TLS Redirects</a></b></div><br />
<br />
Almost three years ago <a href='https://www.hackthissite.org/news/view/718' target='_new'>we wrote about</a> using GitHub for providing a sort of HTTPS wrapper around our <a href='https://www.statuscake.com' target='_new'>StatusCake</a> status pages. StatusCake does provide HTTPS status pages, but their free plan only offers URLs like <a href='https://uptime.statuscake.com/?TestID=4TC8WjmZ8X' target='_new'>https://uptime.statuscake.com/?TestID=4TC8WjmZ8X</a> and we wanted to use our own sub-domains like <a href='https://status.hackthissite.org' target='_new'>https://status.hackthissite.org</a>. Our domains use <a href='https://en.wikipedia.org/wiki/HTTP_Strict_Transport_Security' target='_new'>HTTP Strict Transport Security (HSTS)</a>, which enforces HTTPS on all sub-domains, so our status page URLs would also require an HTTPS protocol. We originally used a VPS to serve the HTTPS status sub-domains (first as a redirect and later as a frame), which created a single point of failure. So we switched to using <a href='https://docs.github.com/en/github/working-with-github-pages/about-github-pages' target='_new'>GitHub Pages</a> (which we described in a <a href='https://www.hackthissite.org/news/view/718' target='_new'>prior blog post</a>). This was fine for some time, but then web browsers received updates that eventually broke this.<br />
<br />
The main problem was that we were using frames to load the StatusCake status pages. We lacked control over what HTTP response headers GitHub would send, including cache settings and <a href='https://en.wikipedia.org/wiki/Cross-origin_resource_sharing' target='_new'>Cross-origin resource sharing (CORS)</a>, so updating these frames to support modern standards across common browsers and extensions proved to be challenging. But we also lacked visibility. GitHub pages do not provide any statistics. Frames were just too much of a hassle and we wanted traffic insights, so a new solution was needed.<br />
<br />
Enter: <a href='https://redirect.pizza/?utm_source=partner&amp;utm_medium=banner&amp;utm_campaign=hackthissite.org' target='_new'>Redirect.Pizza</a><br />
<br />
<div align="center"><img src='https://data.htscdn.org/images/redirect-pizza-config.png' /></div><br />
<br />
There are many redirection services out there. In fact most domain registrars offer this. But almost none of them provide HTTP<u>S</u> redirects, which conflicts with HTTP Strict Transport Security, and fewer still provide any visibility. <a href='https://redirect.pizza/?utm_source=partner&amp;utm_medium=banner&amp;utm_campaign=hackthissite.org' target='_new'>Redirect.Pizza</a> has all of these features, especially HTTPS redirects and aggregate analytics, and can even provide frames if we ever wanted to return to that model. It also supports a lot of <a href='https://redirect.pizza/features?utm_source=partner&amp;utm_medium=banner&amp;utm_campaign=hackthissite.org' target='_new'>other features</a> that we could use, such as variable redirect URLs, URI and query string forwarding, and an API.<br />
<br />
Of course, we could have returned to using a VPS again or used something like AWS CloudFront to provide HTTPS redirects, but these have their own downsides including a lot of costing money that <a href='https://www.hackthissite.org/donate/' target='_new'>we simply do not have</a>. Instead we partnered with <a href='https://redirect.pizza/?utm_source=partner&amp;utm_medium=banner&amp;utm_campaign=hackthissite.org' target='_new'>Redirect.Pizza</a> because they provided all of the features we need (and more) with a very straightforward configuration and <i>aggregate</i> analytics (they don't track individual users but rather overall stats by URL and country).<br />
<br />
This is now live for all of our status pages, which you can find below:<ul><li><a href='https://status.hackthissite.org' target='_new'>https://status.hackthissite.org</a></li><li><a href='https://status.htscdn.org' target='_new'>https://status.htscdn.org</a></li><li><a href='https://status.hts.io' target='_new'>https://status.hts.io</a></li><li><a href='https://status.cryptopaste.org' target='_new'>https://status.cryptopaste.org</a></li></ul><br />
<br />
Finally, we want to send a big thank you to the <a href='https://enflow.nl' target='_new'>Enflow</a> team (the makers of <a href='https://redirect.pizza/?utm_source=partner&amp;utm_medium=banner&amp;utm_campaign=hackthissite.org' target='_new'>Redirect.Pizza</a>) for partnering with and supporting HackThisSite! Partnerships like this keep HackThisSite online and enable us to continue providing our ethical hacking playground for new generations of security experts. If you would like to support HackThisSite, you can always <a href='https://www.hackthissite.org/donate/' target='_new'>donate to us</a>, or reach out to us on <a href='https://twitter.com/hackthissite' target='_new'>Twitter</a> or <a href='https://legal.hackthissite.org/contact' target='_new'>by email</a> if you would like to partner with us, too.</div> <br /><br />
